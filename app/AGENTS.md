# Buy Me a Share — app

Tip jar where the tip becomes a Tessera pre-IPO T-Token. The fan pays in SOL or USDC, Jupiter swaps it into T-OpenAI / T-Kalshi / T-SpaceX and delivers it to the creator's wallet, optionally locked with Jupiter Lock for a duration the fan picks (up to 5 years). No signup and no database: the link is the creator's wallet, and the jar is read from mainnet.

## TL;DR

```fish
cd app
cp .env.example .env.local   # optional; defaults to the public mainnet RPC
pnpm install
pnpm dev                     # http://localhost:3000
pnpm build && pnpm start
pnpm lint
```

Try it with a real T-OpenAI holder: `/tip/EXvTtxurWBUNNCtLojaN8ZBJFNJPZFSH3szoih9hh7YW?name=Ana&x=ana` and `/jar/EXvTtxurWBUNNCtLojaN8ZBJFNJPZFSH3szoih9hh7YW`.

### End-to-end on a local mainnet fork (never real mainnet)

```fish
surfpool start --network mainnet --no-tui --no-studio --no-deploy --airdrop-amount 0 -y   # 127.0.0.1:8899 (binary: ~/.local/bin/surfpool)
set -x RPC_URL http://127.0.0.1:8899; set -x NEXT_PUBLIC_RPC_URL http://127.0.0.1:8899
pnpm e2e:surfpool        # 7 steps: tip USDC->T-OpenAI, tip SOL->T-SpaceX, locked 120s tip, listLocks, claim after time travel, reclaim deposit, jar
pnpm build && pnpm start -p 3100 &   # server builds Blink txs against RPC_URL
set -x BLINK_BASE http://localhost:3100
pnpm blink:simulate      # Blink GET shape, POST guard rails, POST txs simulate with sigVerify:true on the fork
```

Both scripts refuse non-local RPCs. Wallets: `~/.config/solana/stocklana-test.json` (fan) and `~/.config/solana/stocklana-creator.json` (creator), overridable with `FAN_KEYPAIR` / `CREATOR_KEYPAIR`; loaded in-process, never printed. `e2e:surfpool` funds them with Surfpool cheatcodes (fan 1 SOL + 20 USDC, creator 0.05 SOL) and time-travels the chain clock with `surfnet_timeTravel`. Quotes come from the real Jupiter API while execution happens on the fork, so a route can fail with a DLMM `6002`/Jupiter `0x1770` (fork state divergence) or `Failed to fetch accounts from remote` (Surfpool datasource): both scripts retry with a fresh quote. For UI testing on the fork run `pnpm dev` with the same two RPC vars (+ `NEXT_PUBLIC_DEMO_LOCK_SECONDS=120`).

## How the jar is read (no database)

1. `getParsedTokenAccountsByOwner(creator, Token-2022)` → keep the three T-Token mints → holdings.
2. `getSignaturesForAddress` on each of those token accounts (last 100). RPC returns the memo text (`"[14] buymeashare:v0"`), so tips are filtered **without** fetching every tx.
3. For up to 25 tagged signatures, `getParsedTransaction` → net amount = post − pre balance of the creator's account (already net of the 0.2% transfer fee), fan = fee payer. Claims of locked tips carry `buymeashare:v0 kind=claim` and show as "claimed locked tip".
4. USD value = amount × the price picked by `PRICE_SOURCE`.

Locked tips never touch the creator's token account until claimed (they sit in a Jupiter Lock escrow), so they come from `listLocks` instead.

## Transaction layer (`lib/tip`, ported from `../spike/`, which this app must not import from)

| Function | What it builds / returns |
|---|---|
| `buildTipTransaction({ payer, creator, token, payWith, usdAmount, lockSeconds }, { connection? })` → `BuiltTip` | ONE v0 tx. Unlocked: create creator ATA (idempotent) + Jupiter ExactIn swap with `destinationTokenAccount` = creator ATA + memo. Locked: swap into the fan ATA + escrow ATA + `createVestingEscrowV2` (recipient = creator, cliff = **chain** now + `lockSeconds`, cancel NONE, amount = minOut − fee(minOut) so it can never fail on funds) + memo. Walks the maxAccounts shrink ladder until it fits 1232 B. Validates min $1 / $5 locked and max 5 years |
| `buildClaimTransaction({ recipient, escrow })` | claimV2(max) + creator ATA. Throws `TipError` `CLIFF_NOT_REACHED` before the cliff (the program would accept the claim and move 0), `NOT_RECIPIENT`, `NOTHING_TO_CLAIM` |
| `buildCloseEscrowTransaction({ sender, escrow })` | closeVestingEscrow: rent (~0.0051 SOL) back to the fan. Throws `NOT_ESCROW_CREATOR`, `NOT_FULLY_CLAIMED` |
| `listLocks({ creator })` / `listDeposits({ sender })` → `{ locks, chainTime }` | `getProgramAccounts` on `LocpQgucEQHbqNABEYvBvwoxCPsSbG91A1QaQhQQqjn` with `dataSize 296` + discriminator memcmp + recipient (offset 8) or creator (offset 72) memcmp (offsets from the IDL, see `ESCROW_LAYOUT`). Keeps T-Token, non-cancelled escrows. Throws `RPC_UNSUPPORTED` with a hint if the RPC refuses |

All builders return `{ transaction, blockhash, lastValidBlockHeight, bytes }`; the UI confirms with that blockhash. Every tx carries an SPL Memo from `lib/tip/memo.ts`: `TIP_MEMO` (`"buymeashare:v0"`) on tips (or they won't appear in the jar), `kind=claim` / `kind=close` tags on the lock flow.

Signing (locked tips): the escrow base is an ephemeral `Keypair` generated inside `buildTipTransaction`, applied as a partial signature, and returned in `ephemeralSigners` for in-memory use only. In the UI the whole build runs in the browser, so the key never reaches a server; the wallet signs second, and if the wallet rewrote the message the base key re-signs (`hooks/use-send-transaction.ts`). The Blink POST necessarily builds and partial-signs server-side (the key only seeds the escrow address and has no authority afterwards).

Browser gotchas: `@solana/spl-token` uses the global `Buffer` (installed by `lib/solana/buffer.ts`), and Next's bundled `buffer` polyfill has no `readBigUInt64LE`/`writeBigUInt64LE`, so use `u64le` / `readU64le` from that module for u64 fields.

## Env vars

| Var | Default | Notes |
|---|---|---|
| `NEXT_PUBLIC_RPC_URL` | `https://api.mainnet-beta.solana.com` | Wallet + client RPC (tx building in the browser). Public endpoint rate-limits; use a keyed RPC for demos |
| `RPC_URL` | = `NEXT_PUBLIC_RPC_URL` | Server-only RPC: jar/OG reads, `/api/locks` and the Blink POST. **Locked tips and deposits need `getProgramAccounts`**: use a keyed RPC (Helius, Triton, QuickNode). Without it the lock panels show "can't be read on this RPC" instead of failing |
| `NEXT_PUBLIC_SITE_URL` | `VERCEL_PROJECT_PRODUCTION_URL` → `VERCEL_URL` → `http://localhost:3000` | Absolute URLs in metadata/OG/Blink messages |
| `NEXT_PUBLIC_DEMO_LOCK_SECONDS` | unset | Demo only: adds a "Demo" lock unit (UI + Blink) that locks for exactly N seconds, e.g. `120` for the video. Leave unset in production |
| `NEXT_PUBLIC_JUPITER_API_URL` | `https://lite-api.jup.ag` | Swap API (`/swap/v1`), called from the browser and the Blink route |
| `TESSERA_API_URL` | `https://rest-api.tessera.pe/v1/public` | |
| `JUPITER_API_URL` | = `NEXT_PUBLIC_JUPITER_API_URL` | Server price API (`/price/v3`) |

`NEXT_PUBLIC_LOCK_SECONDS` is gone: the fan picks the lock duration.

## Product rules

- Lock: "No lock" by default, or an integer + days/months/years (month = 30 days, year = 365 days), max 5 years. Locked tip minimum $5 (unlocked $1).
- Whenever a lock is selected, show `<LockWarning />` (`TESSERA_LOCK_WARNING`, visible, not a tooltip) and the deposit line "+ ~0.0051 SOL refundable deposit (escrow rent), returned to you after the creator claims" with its live USD value. The Blink POST `message` includes the same warning.
- Prices: `PRICE_SOURCE` in `lib/prices/source.ts` (`"market"` = Jupiter, default, or `"tessera"`) drives every displayed USD value; the other price is shown next to it ("Tessera mark: $X"). Decision pending: change it there only.

## Copy rules (from Tessera's terms)

- T-Tokens are **not** shares/equity/stock. Never write "share", "piece of OpenAI", "own OpenAI", "equity" or "stock" about the token. Say "T-OpenAI" or "OpenAI pre-IPO exposure (Tessera T-Token)". (The product name itself lives in `PRODUCT_NAME`.)
- The Tessera notice (`<TesseraNotice />`) stays on the landing and tip pages.
- Always show "includes 0.2% token transfer fee" next to estimates.
- `name`/`x` from the link are unverified: always show the short wallet next to them and the "unverified" badge.
- Never hardcode a lock duration or its label; use `formatLockDuration()` / `lib/lock.ts`.
